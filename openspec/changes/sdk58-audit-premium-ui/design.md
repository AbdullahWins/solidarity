# Design

## Context

Expo Router app (file-based tabs: Scan, Stats, Leaderboard, Community, Profile, Settings), local-first data in AsyncStorage, optional Firebase Auth + Firestore via the JS SDK. Native folders are generated by `expo prebuild` and gitignored, so every native change must be a config plugin or an `app.json` setting. See proposal.md for motivation.

SDK 58 facts that shape the work:
- Expo Router 58 vendors React Navigation (`ThemeProvider`, `DarkTheme`, `useFocusEffect`, `useIsFocused` are exported from `expo-router`; JS tabs live at `expo-router/js-tabs`). Direct `@react-navigation/*` deps are no longer needed.
- `expo-media-library` legacy functions (`saveToLibraryAsync`) throw at runtime; the replacement is `Asset.create(uri)`.
- The New Architecture is always on; `newArchEnabled` is rejected by the config schema.
- `@firebase/auth`'s React Native `getAuth()` falls back to in-memory persistence with a warning.

## Goals / Non-Goals

**Goals:** clean `expo-doctor`; Play warnings resolved; iOS submission-ready config; audit bugs fixed; responsive premium UI on phone and tablet in both orientations; store-required website.

**Non-Goals:** a light theme (the app stays dark-only and declares `userInterfaceStyle: "dark"`); localisation; server-side (Cloud Functions) enforcement of XP, which stays client-authoritative; replacing JS tabs with native tabs.

## Decisions

1. **Orientation and hardware features.** Set `orientation: "default"` (no `screenOrientation` in the manifest, so no implied `screen.portrait` feature). A new `plugins/withAndroidStoreCompliance.js` adds `<uses-feature required="false">` for `android.hardware.camera`, `camera.autofocus`, `camera.any`, `screen.portrait` and `screen.landscape`, so library manifests cannot reintroduce a hard requirement. The alternative (keeping portrait and only adding the feature override) was rejected because the user wants landscape support and Android 16 ignores orientation locks on large screens anyway.
2. **R8.** `expo-build-properties` handles `enableMinifyInReleaseBuilds` and `enableShrinkResourcesInReleaseBuilds`; the same compliance plugin rewrites `proguard-android.txt` to `proguard-android-optimize.txt` in `app/build.gradle`. Keep rules for the libraries we use are already shipped as consumer ProGuard files.
3. **Images.** Every bitmap goes through `expo-image` (Glide on Android, SDWebImage on iOS), with downsampling and memory/disk caching. In-app logos come from a new 128 px `assets/images/logo.png` instead of decoding the 1024 px icon. Gradients use `expo-linear-gradient`, not images.
4. **Icons.** The original 500 px icon has a white margin baked in. A one-off Pillow script (`scripts/generate-icons.py`) extracts the glyph and produces: a 1024 px opaque full-bleed `icon.png` (iOS), an adaptive `adaptive-icon.png` foreground on transparent background inside the 66% safe zone with `backgroundColor` set to the brand colour, a `monochrome-icon.png` for Android 13 themed icons, a white-on-transparent `notification-icon.png` (Android requires a silhouette), a `splash-icon.png`, and the website's images.
5. **Auth persistence.** `initializeAuth(app, { persistence: getReactNativePersistence(AsyncStorage) })` on native and `getAuth` on web, guarded against double init during Fast Refresh.
6. **Leaderboard privacy.** A new `leaderboard/{uid}` collection holds only `uid, displayName, xp, level, currentStreak, longestStreak, updatedAt`. It is readable by anyone, writable only by its verified owner with field and size validation, and deleted on opt-out or account deletion. `users/{uid}` becomes owner-only. To keep the leaderboard working for users still on 1.0.2, a temporary legacy rule allows listing `users` only for queries constrained to `leaderboardOptIn == true` (Firestore checks query constraints against rules). Ordering by `xp` on `leaderboard` uses the automatic single-field index, so no composite index is needed. The legacy composite index stays until the legacy rule is removed.
7. **Account deletion.** The client calls `reauthenticateWithCredential` first, so a stale session fails before anything is deleted. It then retracts each active vote (tally transactions), deletes the voter docs (the rules now allow owners to delete their own voter doc), deletes `leaderboard/{uid}` and `users/{uid}`, and finally calls `deleteUser`. Allowing voter-doc deletion re-opens "retract → delete → re-vote" XP farming, but XP is already client-authoritative (users can write any XP to their own doc), so the tombstone was not a real control. Accepted.
8. **GTIN handling.** New `lib/gtin.ts`: digits-only; length 12 → prefix `0` (GTIN-13); UPC-E (8 digits, type `upc_e`, or leading `0`/`1` when typed manually and the EAN-8 check fails) → USA & Canada; EAN-8 uses its first three digits as the GS1-8 prefix; 14-digit GTIN drops the indicator digit. Mod-10 check-digit validation is applied to all of these.
9. **Streak reminders.** Replace the single DAILY trigger with up to 7 DATE triggers at 19:00 for the next days, skipping today when the user has already scanned. The schedule is rebuilt on every scan, on app foreground and when the setting is toggled, so it always rolls forward.
10. **Responsive layout.** `hooks/useLayout.ts` exposes `{ width, height, isLandscape, isWide, useRail, columns, contentMaxWidth }`. Breakpoints: `useRail = width >= 700 || width > height`; columns are 1 below 600 dp, 2 below 1000 dp and 3 above. A custom `tabBar` renders either a floating bottom bar or a side rail, and `tabBarPosition` switches to `left` when using the rail. A shared `Screen` component centres content at `contentMaxWidth` (760 dp, or 1100 dp for grid screens), applies safe-area insets for all edges except where the navigator already does, and provides pull-to-refresh. Lists use `FlatList` with `numColumns` keyed by the column count.
11. **Visual language.** Dark-only tokens: layered surfaces (`#07080B` base, `#0E1015`/`#14171E` elevated), hairline borders, a brand coral `#F0643C` taken from the icon for brand moments, a periwinkle interactive accent `#7C9CFF`, emerald positive and rose negative. Gradient hero cards, 20–24 dp radii, tabular numerals for stats, a pressable scale animation on buttons, and Reanimated entry transitions. Haptics stay behind the existing preference.
12. **iOS readiness.** `ios.infoPlist` sets `ITSAppUsesNonExemptEncryption: false`; `ios.privacyManifests` declares the UserDefaults (CA92.1), FileTimestamp (C617.1), SystemBootTime (35F9.1) and DiskSpace (E174.1) reasons; `requireFullScreen: false` with all orientations for iPad multitasking; `expo-media-library` gets `isAccessMediaLocationEnabled: false`. The photo-add purpose string is set; there is no read access. No social logins are used, so Sign in with Apple is not required (guideline 4.8). In-app account deletion exists (5.1.1(v)).
13. **Website.** Plain HTML/CSS in `website/`, deployed by `.github/workflows/pages.yml` to `https://abdullahwins.github.io/solidarity/`. App links are centralised in `constants/app-info.ts`. Unknowns (developer name, contact email, governing law, App Store ID) are single placeholders, listed for the owner to confirm.

## Risks / Trade-offs

- [Rules deploy is out of band] → README and the final summary call it out. The new client tolerates old rules: leaderboard writes fail silently, and deletion still removes the user doc and auth account.
- [Legacy clients keep writing `users/{uid}` with `leaderboardOptIn` and `myVotes`] → the legacy list rule only exposes opted-in users, as before. Remove it once 1.0.2 adoption is negligible.
- [Landscape camera preview] → `CameraView` handles rotation, and the viewfinder is sized from the layout, not a fixed height.
- [Regenerated icon quality from a 500 px source] → the glyph is upscaled with Lanczos and edge re-sharpening. A vector master would be better; noted as an open question.
- [TypeScript 6 / React 19.3 typing drift] → verified with `tsc --noEmit` and `expo lint`.

## Migration Plan

1. Deploy `firestore.rules` (`npx firebase deploy --only firestore`).
2. Ship app 1.1.0 (versionCode 19, iOS build 1). Opted-in users re-appear on the new leaderboard after their next sync. Their first launch also backfills the entry.
3. Push `website/` to `main` and enable Pages (Source: GitHub Actions). Paste the URLs into Play Console and App Store Connect.
4. Rollback: the old app keeps working against the new rules (legacy list rule). Reverting the rules restores the old behaviour.
